# Validation status

Version 0.1.0 was exercised on a deterministic, generated 2D TIFF acquisition and through the local browser. No real experimental images, cell trajectories or user reviews are included in the repository. Synthetic images are generated by code into a chosen output directory.

## Automated checks

`python -m pytest microscopy/tests plate_reader/tests` includes the existing plate-reader suite and microscopy checks for:

- Known first-division intervals, subsequent daughter persistence, loss and whole-recording no-division outcomes.
- Immutable result snapshots and original run preservation after edits/reruns.
- Optimistic revision conflicts, undo, same-run review imports, refusal of cross-run imports.
- Two initial cells becoming separate founders, no inherited ambiguous links, and exclusion of the original from fluorescence counts.
- Invalid/intersecting/out-of-bounds outlines; corrected masks changing quantitative area/signal.
- Manual structure-quality exclusions, gap handling, and explicit full-window verification.
- Additive fluorescence background correction, negative values, exposure scaling prerequisites and missing exposure/channel behavior.
- Event-relative frame selection, alternate tracker execution and validation of segmenter/graph contracts.
- Unsupported TIFF dimensions, no inferred timing/exposure, and changed raw image detection.
- Exact unit-level permutation tests; duplicating cells without adding units does not change inferential sample size or p-values.
- Local HTTP review saves, origin protection, image rendering and result-path containment.

The CI workflow runs both suites on Python 3.10 and 3.12. Local validation used Python 3.10 with the declared package dependencies, and openpyxl 3.1.5 for the pre-existing plate-reader tests. An older installed openpyxl caused an existing long-duration spreadsheet parser test to fail; it passed in the isolated test environment with 3.1.5. No plate-reader implementation was changed.

The skill passes the skill-creator frontmatter/scaffold validator. The package installs from `pyproject.toml`; JavaScript syntax is checked separately. The browser was inspected with the synthetic project, including phase/PI outlines, a saved decision, undo, and regeneration reflecting the resulting review revision. Polygon rasterization/splitting and link editing are covered in backend tests; not every gesture or browser/operating-system combination has been tested manually.

## What remains to validate on the next real folder

1. Confirm acquisition mapping, elapsed-time origin, exposures and channel alignment against the microscope metadata.
2. Review a representative set of candidate founders across positions, including ambiguous initial cells, focus issues, motion, merges and late divisions. Quantify segmentation/identity/event errors against adjudicated examples where conclusions depend on them.
3. Calibrate segmentation, isolation and focus choices for those optics and cell morphology. A focus score or threshold from the previous experiment is not automatically transferable.
4. Verify fluorescence masks and local background regions; inspect empty regions, saturation, exposure linearity and potential condition-specific optical/staining differences.
5. Confirm the experimental unit and planned comparisons. Multiple fields are not necessarily independent cultures. Distinguish descriptive analyses from supported inference.
6. Check memory, latency and review ergonomics at the actual acquisition size before expanding a pilot. The current graph is held in memory; the application is not benchmarked on multi-terabyte data.

A new model should be compared on the same adjudicated cases before replacing an existing adapter. Improved track retention alone is not evidence of improved identity accuracy. Legacy review migration requires separate fixtures and fidelity checks and is not validated here.
